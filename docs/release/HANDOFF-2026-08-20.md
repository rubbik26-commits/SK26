## 1. What the job is

`https://lucia-ru5s.onrender.com` must serve **exactly** what
`https://nycremarketintel.com` serves — same keys, same **key order**, same values,
same status codes, same error bodies. The only two permitted differences in the whole
product are:

1. Skyline Properties branding and colours.
2. Mobile responsiveness / element overlap / interaction blockers.

An extra key the original does not publish is a defect. A missing key is a defect. A
different key order is a defect. This is the full **Owner** build (`APP_VARIANT=owner`);
nothing is reduced. The user-facing variant is the owner build with surfaces hidden, so
the owner build has to be complete first.

`/home/user/lucia/CLAUDE.md` is the operating protocol. Read it before touching
anything. The rules that bite hardest in practice:

- Never claim done without a pasted probe.
- Never guess. Unknown cause → write exactly `I do not know the exact cause of this yet`.
- **Confirm by measurement which handler production serves before patching a route.**
  Mount order in `server.js` decides; `docs/release/route-table.md` goes stale.
- Never fabricate property data. An empty state is correct; a plausible fake number is a
  critical defect. An absent figure must stay `null`/absent, never become `0` or `""`.
- Never remove a file, function, variable, config key, comment or log line. If the
  original does not *publish* something, keep computing it and stop publishing it, with a
  comment recording the measurement. See `server/market-report.js` for the house pattern.

## 5. Decisions that belong to the owner, not to an engineer

Each of these would remove a working surface, so none was closed unilaterally. All three
are measured.

1. **`/api/investors`** — the original answers `200 {"owner":false,"investors":[]}` to
   **every** HTTP method. The rebuild registers GET and POST only, so the other five now
   get 405 from the method guard. Its POST also differs: original 200, rebuild
   `400 {"error":"bad_payload"}`.
2. **`POST /api/pipeline`** — the original answers **405**. The rebuild registers POST for
   the kanban writes. Matching the original disables those writes.
3. **Routes the original does not have at all** — `/api/status`, `/api/auth/signup`,
   `/api/user/saved`, `/api/account/delete` all answer
   `404 {"error":"Not found"}` on the original but are served by the rebuild. Note that
   `/api/status` may be what a dashboard-configured Render health check points at
   (`render.yaml` health-checks `/healthz`; see the comment in `server/gate.js`).

**The method guard itself** (`server.js`, commit `270b37a`) is landed and measured:
the original enforces a **per-route method allow-list**, not blanket GET-only. A routed
path asked with the wrong method → `405 {"error":"Method not allowed"}`,
`application/json; charset=utf-8`, **no `Allow` header**. `/healthz` answers the same
status as `text/plain` `Method Not Allowed`, and allows GET **and HEAD**. An unrouted path
→ `404 {"error":"Not found"}` for every method. After: **97/105 status matches**, bodies
byte-identical. The 8 residuals are exactly the three items above.

One trap encoded there: an unrouted path must **fall through** the early guard rather than
404 immediately, because the local-auth paths are closed in production by *middleware*,
not by a route. 404ing early stole that `410 Gone`
(`tests/account-store-degradation.test.mjs`, "no local-auth path can create a session").

## 7. How to measure — do not rediscover this

**Gate both sides.** Both are behind a password wall.

```
Original: POST https://nycremarketintel.com/__gate
          content-type: application/x-www-form-urlencoded
          body: password=creintel2026        redirect: 'manual'
          keep the Set-Cookie values, send them back as `cookie`

Rebuild:  POST <base>/__gate  with password = process.env.SITE_PASSWORD
```

**`APP_VARIANT=owner` rewrites `OWNER_PASSWORD` to `SITE_PASSWORD` at boot**
(`server/owner-variant.js:22`). So in the owner build, `SITE_PASSWORD` *is* the owner
tier, and the configured `OWNER_PASSWORD` value is rejected by the gate. This costs an
hour if you do not know it.

**Running a server:** `PORT=<n> APP_VARIANT=owner node server.js`. Never use `pkill` with
a pattern to kill it — a pattern like `node server.js` matches the shell running the
command and kills your own session. Scan `/proc/*/cmdline` for the exact string instead.

**Parallel agents:** the harness caps concurrent agents at `min(16, CPUs - 2)`. This box
has 4 CPUs, so **2 agents at a time**, which is a poor fit because the work is
network-bound, not CPU-bound. The cap is **per workflow**, so launching a second workflow
on non-overlapping files doubles throughput. File ownership must be strictly disjoint, or
two agents will fight over one file.

## 8. Residuals that are genuinely unsolved

Stated plainly rather than papered over.

- **`/api/footprints` selector.** I do not know the exact cause of this yet.
- **`/api/market-report` `MIN_PPSF_GROSS_AREA`.** Measured: a 400 sf row is excluded, a
  450 sf row included. No sale anywhere in the city in this window has a
  `gross_square_feet` strictly between them, so every threshold in `[401, 450]` reproduces
  every available measurement. `> 400` was implemented as the only round constant in the
  bracket. The original's own constant is unobservable from outside.
- **`/api/territory` sales thresholds.** `ppsf > 10` is pinned tight (9.770083 out,
  10.076616 in). `ppsf < 20000` is bracketed to `(17675.4, 21973.2]` and `sf > 200` to
  `[200, 231)` — no sale exists in either gap to decide them. Round numbers were chosen
  inside each bracket; they reproduce 77/77 solved pairs and 226/228 live probes.
- **`ownersByBuildings` tie order**, 2 of 228 territory probes. Proven nondeterministic
  **upstream**: five identical calls to the original returned two distinct orders, and the
  same query straight to Socrata did the same. There is no rule to recover.
- **`/api/market-report` LL84 row selection on campus BBLs.** On `2031200020` the original
  publishes the *first* row carrying a GHG (2,233 t) rather than the largest (19,684 t);
  on `2026050040` it publishes the *largest* (93,318 t) rather than the first (2,555 t);
  on `4059170001` it publishes `null` although seven 2024 rows carry a GHG. Those three
  cannot all be true of one deterministic rule over an unordered page. I do not know the
  exact cause of this yet.
- **Response headers differ globally.** The rebuild adds `x-content-type-options`,
  `x-frame-options`, `referrer-policy`, `permissions-policy`,
  `cross-origin-resource-policy`, `access-control-allow-credentials` and `ratelimit-*`,
  none of which the original sends; the original uses `br` where the rebuild uses `gzip`.
  These come from `server/security.js` and the `cors`/`compression` middleware. They may
  be sanctioned hardening rather than a defect — an owner decision, not an engineering one.
